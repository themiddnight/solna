# Harmony Scales Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the 8 scales ADR-0054 left out (Bebop, Bebop Major, Bebop Minor, Whole Tone, Diminished, Double Harmonic Major, Hungarian Minor, Flamenco). Each one names a 7-note `harmony` scale. Chord-side code reads the harmony scale, and note-side code reads the scale itself.

**Architecture:** `ScaleDefinition` gains an optional `harmony` (a SCALES key). A new Music Core helper, `harmonyKey(scaleType)`, returns `SCALES[k].harmony ?? k`, with `k` resolved by `resolveScaleKey`. Every chord-side read (degree qualities, Roman numerals, diatonic and borrowed chords, snap, the chord palette, progression availability, Chord mode, the pad drone degree, bass diatonic steps) goes through `scaleEntry(harmonyKey(scaleType))`. Note-side reads (scale notes, scale lock, melody rows, remap, spelling) stay on `scaleEntry(scaleType)`. Task 1 is a pure refactor: for all 24 existing scales `harmonyKey` is the identity, so the characterization fixtures must not move. Task 2 adds the data.

**Tech Stack:** Bun (test runner, scripts), TypeScript, React 19 (`renderToString` tests only), `tonal` (confined to `src/musicCore/tonalAdapter.ts`), ESLint, Knip.

**Spec:** `docs/superpowers/specs/2026-09-26-harmony-scales-design.md` (binding). Read it before Task 1.

## Review Focus

1. **The phone's scale-locked rows on an 8-note scale hold all eight degrees.** Today the home row starts `2n-3` steps below the tonic and runs 11 keys. For `n = 8` it ends at step -3, so the lower touch row (R340) loses the octave-down A and B of C Bebop Major. Expected: both touch rows have 8 keys, the lower one an octave under the upper. Pinned in Task 3.
2. **Chord mode never binds a triad to a melody-row key, for any scale.** If Chord mode read the scale's own 8 degrees, the 8th triad would take `HOME_ROW_KEYS[7]` = `KeyK`, which is `MELODY_KEYS[0]`, and one key would fire two things. Pinned in Task 3 by a test over every SCALES key.
3. **A lead melody remaps by degree on a scale change.** The spec keeps remap on the note side, so Major → Bebop Major moves A4 to G#4, and Bebop Major → Major moves G#4 to A4 while B4 (degree 7, no Major home) stays put. That is surprising but deliberate. Pinned in Task 4 so it stays a decision, not an accident.
4. **A harmony scale's borrowed palette equals its harmony's.** F minor is built from C Bebop Major's own notes (F, G#, C), but the Major palette lacks it, so it is still offered as borrowed. If the filter read the scale's notes, F minor would silently vanish. Pinned in Task 2.
5. **A key-change snap into Whole Tone lands every chord on a Lydian Augmented palette chord and never throws.** The landing chord may have a root outside the scale (A). Pinned in Task 2.

## Rulings

The spec leaves these open. This plan decides them as follows.

1. **`getBorrowedChords` is chord side all the way through.** The per-scale list match, the `isDiatonic` filter and the palette filter all read `harmonyKey(scaleType)`. The spec's test ("Bebop Major equals Major's") requires this: read on the scale's notes, `isDiatonic` would drop F minor (F, G#, C are all in C Bebop Major) although the Major palette lacks it. A side effect: an unknown `scaleType` now takes the Major list, because `harmonyKey` resolves the fallback, where it used to take the default list filtered against Major. After `sanitize`, no unknown `scaleType` reaches this.
2. **The pad drone's `intervals` are not a scale read.** The spec says "the drone's intervals". The `intervals` in `padPlan.ts`, `padPlayback.ts`, `songSnapshot.ts` and `playbackPlanSnapshots.ts` are the user's `PadInterval` set (1/4/5/8/12), not scale intervals. The drone's **root** comes from `getDiatonicChordForDegree`, which is chord side after Task 1, and its **buttons** come from `droneDegreeButtons` (Task 3). Neither playback file changes.
3. **The scale-locked home row is capped for 8-note scales.** `homeRowStart = -Math.min(2 * scaleLength - 3, HOME_ROW_KEYS.length)`. For `n ≤ 7` this is the old `-(2n-3)`, byte for byte. For `n = 8` it is `-11`, so the home row ends on the step just below the tonic and the phone's lower row keeps all eight degrees. The trade: on an 8-note scale `KeyA` plays the 6th degree two octaves down, not the 4th.
4. **One palette helper.** A new exported `getDiatonicChords(root, scaleType, use7ths)` in `utils/musicTheory.ts` returns one `getDiatonicChordForDegree` result per degree of the harmony scale. `isInScalePaletteChord` and `useChordView`'s palette both use it, so the palette's degree count is read in one place.
5. **The Chord-mode melody row stays note side.** It plays the scale's own notes (G# included on Bebop Major), like the scale lock.
6. **Test helpers and generators that count chord degrees switch to `harmonyKey`**, because otherwise they iterate a degree that hosts no chord: the diatonic characterization generator and test, the `musicTheory.test.ts` palette helper, the borrowed-duplicate test, the snap test and the registry-emission test, `ChordPresetLibrary.test.tsx`, `chordProgressions.test.ts` (`minScaleLength`, `expectedRomanNumeral`) and `vibeVariation.test.ts`. The last two cover only existing scales, so their results do not change. They switch so that R358's Prohibited line holds everywhere.
7. **R078–R080 measure the harmony scale.** Whole Tone has 6 notes, but its numerals carry Lydian Augmented's accidentals (`#iv`, `#v`). R358's text says so.
8. **Sanitize falls back to the loop default, not Major.** The spec says "an unknown key still falls back to Major". `sanitizeLoops` falls back to the default loop's `scaleType` (`Natural Minor`), as the existing `bogus-scale` test pins, and that stays. The Major fallback lives in `resolveScaleKey`/`harmonyKey` and is pinned there (Task 1).
9. **`scripts/verify-borrowed.mts` is left alone.** It is a throwaway research script, outside `verify`.
10. **Where the tests go.** The spec lists the new behaviour tests under `musicTheory.test.ts`. That file is near the `max-lines` gate, so they go in a new `src/utils/harmonyScales.test.ts`. The `harmonyKey` tests go in `src/musicCore/scale.test.ts`, beside `resolveScaleKey`, because `harmonyKey` lives there.
11. **`parentDegreesFor` is unchanged.** It takes whatever key it is given, and `resolveDegreeQuality` hands it `harmonyKey(scaleType)`. The equidistant-tie test in `scales.test.ts` still counts exactly two ties.
12. **No `CLAUDE.md` edit.** `.claude/rules/music-domain.md`'s `paths:` already cover every chord-side file (`src/utils/musicTheory.ts`, `src/components/ui/Keyboard.tsx`, `src/components/loop/chord/**`, `src/audio/bassPatterns.ts`, `src/audio/playback/padPlayback.ts`), so R358 loads wherever it applies.
13. **Remap stays by degree** (Review Focus 3). This follows the spec. A harmony-aware remap is out of scope, and Task 4 pins today's result.

```ts
/**
 * The in-scale palette: one diatonic chord per degree of the scale that hosts
 * the chords (R358). Seven for Bebop Major, whose passing tone hosts none;
 * five for Hirajoshi, whose own degrees do.
 */
export function getDiatonicChords(
  root: string,
  scaleType: string,
  use7ths: boolean,
): { root: string; quality: ChordQuality; degreeName: string }[] {
  return scaleEntry(harmonyKey(scaleType)).intervals.map((_, degree) =>
    getDiatonicChordForDegree(degree, root, scaleType, use7ths),
  );
}

// True when the in-scale palette (triads or 7ths) renders the same root+quality.
```

```markdown
# ADR-0057: Harmony scales

**Status:** Accepted — 2026-09-26. Amends [ADR-0054](0054-derived-scale-intervals.md) (R061). No issue.

## Context

ADR-0054 left out eight of murva's scales: Whole Tone, Diminished, Bebop (Dominant), Bebop Major,
Bebop Minor, Double Harmonic Major, Hungarian Minor and Flamenco. Harmony in the app assumes a
7-note tertian scale, and `parent` covers only subsets of one (the pentatonics and blues). Probing
the eight showed two failures:

- **Passing tones.** The three bebops have 8 notes. Stacking thirds over the passing tone gives
  chords no player would use, and the extra degree shifts every degree-indexed progression: vi in
  Bebop Major lands on G#.
- **Degrees with no chord.** In Whole Tone, Diminished, Double Harmonic Major, Hungarian Minor and
  Flamenco, some degrees stack to interval tuples outside the quality tables, and some have no
  third in the scale at all (degree 7 of Double Harmonic Major). A `parent` does not help either,
  because their notes lie outside every candidate parent.

murva maps each of these scales to a "closest diatonic approximation" (its `parentMapping`), but
coarsely, to major or minor.

## Decision

- `ScaleDefinition` gains an optional `harmony`: the SCALES key of a 7-note scale whose chords
  the scale uses wholesale. Its own degrees host no chords. A scale sets `parent` or `harmony`,
  never both, and the harmony scale sets neither.
- `harmonyKey(scaleType)` in `src/musicCore/scale.ts` returns `SCALES[k].harmony ?? k`, with `k`
  from `resolveScaleKey`, so the Major fallback stays in one place.
- **Chord side** reads `scaleEntry(harmonyKey(scaleType))`: degree qualities, `degreeToRoman`,
  `getDiatonicChordForDegree`, `getDiatonicChords` (the palette), `getBorrowedChords` (list and
  both filters), `snapProgressionToScale`, progression availability, keyboard Chord mode, the pad
  drone's degree buttons, and bass diatonic steps. **Note side** reads `scaleEntry(scaleType)`:
  scale notes, `isNoteInScale`, `remapNoteByScaleDegree`, the scale-locked keyboard, the melody
  grid rows, the Chord-mode melody row, the arp and display spelling.
- The map, chosen by the user in detail over murva's coarse one:

  | Scale | harmony | Why |
  |---|---|---|
  | Bebop | Mixolydian | the scale minus its passing tone |
  | Bebop Major | Major | the scale minus its passing tone |
  | Bebop Minor | Dorian | the scale minus its passing tone |
  | Whole Tone | Lydian Augmented | shares 5 of its 6 notes; an augmented I |
  | Diminished | Locrian #2 | shares 6 of its 8 notes; the diminished i stays in the scale |
  | Double Harmonic Major | Phrygian Dominant | shares 6 of 7; keeps the bII–I cadence |
  | Hungarian Minor | Harmonic Minor | shares 6 of 7 |
  | Flamenco | Phrygian Dominant | murva's own mapping; the Andalusian major I |

- `tonality` stays authored. Its invariant reads the harmony scale's third, which is right for
  Bebop Minor (it holds both thirds and reads minor) and for Flamenco (its major I comes from
  Phrygian Dominant).
- Names, descriptions and categories are murva's. A new last category, `Jazz & Other`, holds the
  bebops, Whole Tone and Diminished; the other three join World.
- The scale-locked keyboard's home row starts at most 11 steps below the tonic, so an 8-note
  scale's phone rows keep all eight degrees. For 7 or fewer notes the start is unchanged.

Rejected:

- **A fit-search harmonizer** that picks the best-fitting chord per degree. It leaves chordless
  degrees, and an 8-degree scale still breaks degree-indexed progressions.
- **New chord qualities** for these scales (7b5, sus b5). They fill only some of the holes.
- **murva's coarse major/minor map.** The user declined it: it loses Whole Tone's augmented I and
  the Phrygian Dominant cadences.
- **Filtering borrowed chords against the scale's own notes.** F minor is built from C Bebop
  Major's notes, but the Major palette lacks it, so it would vanish from both lists.

## Consequences

- A chord can contain a note outside the scale. Whole Tone's chords include Lydian Augmented's A,
  which the scale-locked keyboard cannot play and the melody grid shows as a borrowed row. The
  "In-Scale Chords" heading stays as it is. murva makes the same trade.
- A harmony scale inherits its harmony's borrowed list and Roman-numeral accidentals: Whole Tone
  reads `#iv` and `#v`, although it has six notes.
- A seven-degree progression is offered in Whole Tone.
- A lead melody still remaps by the scale's own degree on a scale change, so Major → Bebop Major
  moves A to G#. A harmony-aware remap would be a separate decision.
- Adding a scale whose degrees host no chords is one SCALES entry naming its `tonal` scale and a
  7-note `harmony`. The characterization fixtures gain lines, and none of the existing ones move.

## Rules this implies

- **R061** (amended) — `SCALES` states at most one chord source: a 7-note `parent` for a scale
  under seven degrees whose own degrees host chords, or a `harmony` (a 7-note key setting
  neither) for a scale whose degrees host none.
- **R358** — chord-side code reads `scaleEntry(harmonyKey(scaleType))`; note-side code reads
  `scaleEntry(scaleType)`; R078–R080 measure the harmony scale.
```
